# LinkDigest 架构

## 定位

输入一个媒体链接，输出一份可核对的内容总结报告。全链路的采集、转写、清洗用开源框架完成；
只有「理解与归纳」交给模型。换模型不影响管道，换引擎不影响模型。

## 三条硬约束

| 约束 | 理由 | 代价 |
| --- | --- | --- |
| 视频只取音轨，永不抓帧 | 抓帧+视觉理解的算力与复杂度是音频链路的 5-10 倍，而 90% 的信息在语音里 | 图表/演示型内容会丢信息（用「评论区/简介文本」做低成本补偿，二期） |
| 不设独立翻译阶段 | 开源 MT（NLLB / Opus-MT）长文本质量只够 gist，且错误会叠加进总结 | 无法输出高质量双语全文（作为独立功能，按需挂载） |
| 确定性层与智能层只通过 `Transcript Bundle` 通信 | 上下游解耦，任一侧可独立替换与测试 | 契约一旦变更是破坏性变更，需要版本号 |

## 分层

```
┌─ 确定性层（全开源、可复现、可单测）─────────────────────────┐
│ ingest        平台判定 + yt-dlp / feedparser / trafilatura / podcast / 本地文件 │
│ capabilities  ffmpeg（-vn -ac 1 -ar 16000）｜speech（faster / mlx）｜ocr        │
│ clean         标点/normalize、时间戳、幻觉、重复、碎片合并    │
│ contracts     Pydantic 契约 + 机械切章 + 校验 + schema 导出    │
└──────────────────────┬──────────────────────────────────────┘
                       │  Transcript Bundle (JSON, schema v1.0)
┌──────────────────────┴──────────────────────────────────────┐
│ 智能层（可替换、可降级）                                      │
│ understand    chunk → map(并行) → reduce → Report(JSON)       │
│ handoff       无密钥时导出作业单，交给外部 agent 理解         │
│ render        Report → Markdown / HTML                        │
└─────────────────────────────────────────────────────────────┘
```

代码目录与依赖方向（只允许向下依赖，跨层反向 import 一律视为 bug）：

```
conventions  ←  config  ←  net  ←  capabilities  ←  contracts
                                    ↑                    ↑
                                  clean  ←  ingest  ←  understand  ←  render
                                                          ↑           ↑
                                                        handoff  ←   jobs
                                                          ↑
                                                         app  →  api / cli
```

`api.py` 与 `cli.py` 是交付形态，只做装配与格式化；用例在 `app/service.py`，
编排在 `app/pipeline.py`。两个入口共用同一套动作，行为不会分叉。

跨语言发生在 `understand` 的提示层：输入是任意语言的转写稿，输出永远是简体中文。
这样 MT 的错误不会污染事实提取，模型可以直接读到原文。

## 数据流

```
URL ──▶ classify ──▶ fetch ──┬─ 音视频 ──▶ ffmpeg ──▶ ASR ──┐
                             └─ 图文  ──▶ trafilatura(+OCR) ─┤
                                                              ▼
                                                    normalize（规则清洗）
                                                              ▼
                                              Transcript Bundle（落盘 + 校验）
                                                              ▼
                                          chunk → map×N → reduce → Report
                                                              ▼
                                                    Markdown（前端渲染）
```

没有模型密钥时，`reduce` 这一步不消失，只是换了执行者：

```
Bundle ──▶ degraded_report（抽取式兜底）──▶ handoff/BRIEF.md（元信息 + 三层契约 + 全文）
                                                    │  外部 agent 读、写 answer.json
                                                    ▼
                              apply_answer ──▶ 校验 ──▶ Report ──▶ report.md
```

`answer.json` 的必填只有四项：`one_liner` / `sections` / `body` / `intent`。
`sections` 提供时间码锚点给机器，`body` 提供深度给人；其余八个字段全部可选、无配额。

产物布局：

```
data/jobs/INDEX.md  全部任务的可读索引
data/jobs/<时间>_<平台>_<标题>_<job_id>/
  manifest.json    身份证：标题 / 平台 / 源链接 / 模式 / 产物清单
  source.json      采集元数据 + 采集说明（哪个降级路径生效）
  audio.wav        16k mono（图文源无）
  transcript.json  契约，下游唯一输入
  report.json      结构化报告
  report.md        文本渲染稿
  report.html      单文件网页稿（内联 CSS，可打印/转发）
  usage.json       token/成本/各阶段耗时
  stages.jsonl     append-only 阶段日志
  handoff/         BRIEF.md（作业单）｜transcript.md ｜answer.template.json（只含必填四项）
```

目录名在收尾阶段由 `store.finalize_dir()` 一次性改成可读名，job_id 保留在末尾
（`*_<job_id>` 反查），因此 id 依旧是稳定主键，找内容不靠记忆。

## 关键决策

**ADR-1 视频不抓帧**：抓帧需要场景检测+关键帧去重+视觉模型，链路长度和成本都翻倍，且与「总结内容」的目标弱相关。
被否方案：画面 OCR 补充（仅对屏幕录制类有效，无法泛化）。

**ADR-2 不做独立 MT**：翻译是「理解」的一部分。被否方案：ASR→MT→总结；两次误差叠加，且术语在两跳里不一致。

**ADR-3 机械切章在确定性层**：章节边界（时间轴）由规则确定，模型只负责命名和归纳。好处是模型烂了也有可用结构。
被否方案：完全由模型切章，长内容会切得前后不一致。

**ADR-4 无模型也出报告**：`degraded_report()` 保证结构完整、内容抽取式，并在报告顶部显著标注。
这条保证前端、导出、存储链路永远可测。

**ADR-7 理解为可替换执行者，而非固定 API**：`handoff/` 把「理解」写成一份自包含作业单
（元信息 + 三层契约 + 带时间码全文），任何能读文件、能写 JSON 的 agent 都能接手，
`apply_answer()` 只做校验与渲染。好处：零密钥可用、模型可换、跨语言不必再写一次提示工程；
代价：多一步人工/agent 往返，因此只在 `degraded` 分支触发，配置了模型时完全不出现。
被否方案：内置规则式摘要升级（永远做不出归纳）、内置本地小模型（质量不足以替代对话式 agent）。

**ADR-8 目录名可读、id 仍是主键**：目录名 `时间_平台_标题_<job_id>`，改名发生在收尾，
所有路径通过 `job_dir(id)` 反查（先裸 id 兼容老任务，再 glob `*_<id>`）。
好处：不用开数据库就能定位内容；代价：一次 rename 与一个反查，可忽略。

**ADR-9 交接契约分三层，配额降为建议**：早期 BRIEF 把「落盘格式」「证据纪律」「字数条数」
混在同一个「硬性要求」标题下，结果是外部 agent 把 40 字上限当成标准，26 分钟的内容里
完整论证链被压成几个点。现在拆开：

| 层 | 内容 | 为什么这么定 |
| --- | --- | --- |
| 必填 | `one_liner` / `sections`（时间码锚点）/ `body` / `intent` | 前两个是机器渲染与回查的接口，`body` 是深度出口 |
| 不可违反 | 只用正文、中文输出、时间码真实、矛盾不裁决、答案落盘 | 这五条决定内容能不能被核对，与风格无关 |
| 可选 | 其余八个字段 | 数字容易传成标准，所以不给配额；「按内容判断」写进作业单 |

代价：`answer.json` 的字段集比早期宽，渲染需要处理有/无 `body` 两种形态；
收益：外部 agent 的产出上限从「40 字格子」变成「它自己判断合适的深度」，
而机器该拿到的锚点一个没少。向后兼容靠默认空串 + 缺字段跳过整节实现。

**ADR-10 报告出两种形态，HTML 按「文档」而不是「应用」来做**：`report.md` 服务终端、
版本库、diff 和 agent 读取；`report.html` 服务人读、打印、转发。两者吃同一个 `Report`、
走同一个 `save_report()` 出口，内容不会漂。

HTML 的几个取向：

| 决定 | 理由 |
| --- | --- |
| 默认浅色纸面，跟随系统切深色 | 长文阅读与打印都更稳；报告常被转成 PDF 或发给不装这套工具的人 |
| CSS 全内联、零外部请求 | 单文件可直接当附件，离线可看，也不会因为某个 CDN 挂掉变成白页 |
| 节标题做成小号标签（12px mono） | 让正文里的 `###` 成为视觉主体，长报告才有阅读纵深 |
| 时间码在 YouTube / B 站变成 `?t=` 链接 | 把「可核对」从验收口号变成一次点击，这是产品的核心承诺 |
| 正文与附录都过一遍危险标签过滤 | 内容来自外部 agent，本地工具也按最小权限处理 |

**ADR-11 把「给谁看」从版面里收走，换成标签**：原来摘要区同时放 `intent`（给谁看）和
`one_liner`（讲了什么），两块并列，读者第一眼不知道该看哪句。现在视觉顺序固定为
**标签 → 一句话 → 速览**：标签回答「这是哪一类」，`one_liner` 回答「讲了什么」，
`intent` 退到页脚与 frontmatter，不占首要位置——它是写作时的取舍依据，不是读者第一眼需要的东西。

`tags` 由理解层产出（不是从链接或平台猜的，平台名属于元信息不属于内容），
`_to_report()` 去重并硬截 5 个。`report.md` 的基础信息（标题/日期/来源/平台/作者/时长/
语言/标签/`intent`/任务号）统一进 YAML frontmatter：正文只剩内容和锚点，
Obsidian、Logseq 这类工具可以直接把这些键当元数据用，不需要解析正文。

代价：多一份产物、样式要单独维护、老任务需要 `rerender.py` 补一次；
收益：报告能脱离本机界面独立存在，分享和归档不再依赖这个服务是否在跑。

**ADR-12 外部依赖按端口/适配器隔离，非代码资源移出代码**：早期 `sources.py` 一个文件
1033 行，同时装着链接归一、平台表、cookies 解析、代理探测（会改进程环境）、yt-dlp 适配、
trafilatura 适配、RSS 适配、播客三级路线和十几条中文报错文案。后果很具体：换 ASR 引擎要读
一个和 ASR 无关的文件；改一句报错要在 300 行匹配逻辑里找；`config.py` 一 import 就写
`os.environ`，测试无法在干净环境跑。

现在分两刀：

| 切法 | 内容 | 收益 |
| --- | --- | --- |
| 依赖方向 | 每层只依赖下一层，`api`/`cli` 只做装配 | 换实现只改一个文件，测试可以只 import 一层 |
| 端口/适配器 | `capabilities/<能力>/base.py` 定端口，每实现一个文件，`__init__` 负责发现与派发 | 加一个 ASR 引擎或换一家模型 = 新增文件 + 登记一行，业务代码不动 |
| 资源外置 | 提示词 `resources/prompts/`，版式 `resources/templates/`，报错话术 `resources/messages/`，黑名单 `resources/asr/`，网页 `resources/web/` | 改文案、改模板、改提示词不碰 Python；diff 也干净 |

代价：文件数从 16 个变成 40 多个，跳转成本略高；`importlib.resources` 要求资源随包
分发（`pyproject` 的 `package-data`），漏配就会在安装后 500。收益：一处改一处生效，
且「这个能力能不能换掉」变成了看目录就能回答的问题。

**ADR-5 单进程 + 线程池**：MVP 只跑 1-2 个并发。上 Celery/Redis 是纯负债；瓶颈在 ASR 和网络，不在调度。

**ADR-6 契约先于实现**：先用 JSON Schema 定死 `Transcript Bundle`，再写管道。
好处：ASR 引擎、采集器、报告器可以三人并行改造而不打架。

## 失败与降级矩阵

| 环节 | 典型失败 | 处理 |
| --- | --- | --- |
| 采集 | 平台反爬 / 需要登录 | yt-dlp 失败 → 提示配置 cookie → job failed（不自动反复重试） |
| 文章 | 正文为空 | trafilatura 返回空 → 明确报错「疑似反爬壳」，不生成空报告 |
| 音轨 | 无音轨 / 纯音乐 | ASR 清洗后 0 段 → 明确失败，不产出空报告 |
| ASR | 模型未装 | 启动时 `available_engines()` 暴露给前端，提交前就能看到 |
| 模型 | 无 key / 429 / JSON 残缺 | 无 key → 降级；单块失败 → 跳过该块并记错误；reduce 失败 → 降级并标注 |
| 长内容 | 超时长上限 | `ASR_MAX_SECONDS` 拦截，提示先切分 |
| 契约 | 校验不通过 | 立刻失败，不把脏数据交给模型 |

原则：**能降级就降级并标注，不能降级就失败；绝不静默产出错误内容。**

## 成本与延迟预算（1 小时中文播客，参考值）

| 阶段 | 耗时（M 系列 CPU） | 成本 |
| --- | --- | --- |
| 下载 | 取决于带宽 | 0 |
| ffmpeg | 5-15s | 0 |
| ASR large-v3 int8 | 约 10-25 分钟 | 0 |
| 清洗 | <1s | 0 |
| map（约 15 段 × 6k 字） | 1-3 分钟 | ~$0.01-0.03 |
| reduce | 10-30s | ~$0.002 |

结论：ASR 是绝对瓶颈。要压到实时以内，走 mlx-whisper 或换 SenseVoiceSmall（中文场景），
二者都是换 `ASR_ENGINE`，不影响其它模块。

## 不做的事（当前版本）

- 不做说话人分离（pyannote 模型授权与商用条款需单独确认）
- 不做画面理解 / 幻灯片提取
- 不做登录态、付费墙、DRM 内容
- 不做多语言字幕成品（只做中文报告）
- 不做 A2UI 交互式渲染（二期，见 DETAILED-DESIGN 的扩展点）
