## 网页打不开 / 点了没反应

界面是后端渲染的单页，**必须走 HTTP**。直接双击 `web/index.html`（`file://`）不会工作：
页面里的 `/static/app.js` 会被解析成 `file:///static/app.js`，控制台报
`ERR_FILE_NOT_FOUND`，`/api/*` 同样不存在，点「生成总结」自然毫无反应。

```bash
./run.sh                    # 起服务，并自动打开 http://127.0.0.1:8787/
NO_OPEN=1 ./run.sh          # 只想起服务，不开浏览器
PORT=9000 ./run.sh          # 换端口
```

页面顶部出现「后端未连接」黄条，说明前端活着但请求没到服务；
服务日志里能看到每次请求和每个阶段的耗时。端口被占时 uvicorn 会直接报 `address already in use`。

## 链接跑不动

先跑自检，再谈原因：

```bash
python -m linkdigest.cli --check "<链接>"                 # 连通性 + 代理 + 解析器
curl "http://127.0.0.1:8787/api/diagnostics?url=<链接>"   # 同上，JSON
```

`--check` 会依次尝试直连 → 环境变量里的代理 → macOS 系统代理，逐条打印结果，
最后告诉你哪个解析器接这条链接、有没有可用格式。

输入本身也可能有问题：粘贴的链接会自动清洗，`\?v\=` 这类 shell 转义、`https:\/\/` 这类
JSON 转义、夹在整句里的链接、末尾中文标点、裸域名（自动补 `https://`）都会被还原。
清洗后还不对，就是真不认识了——这时 `--check` 会直说无法识别。

## 报错对照表

| 报错关键词 | 实际原因 | 处理 |
| --- | --- | --- |
| 代理 502 / 连接超时 / connection refused | 服务继承了一个已失效的代理变量，或代理不放行该域名 | `.env` 里钉死 `PROXY_URL=http://127.0.0.1:<端口>` 后重启；启动日志会打印实际出口 |
| 要求登录校验 | 平台判定当前出口为机器人 | 见 [COOKIES.md](COOKIES.md) |
| 内容不可用 / 地区限制 | 内容被删、私有、仅限会员，或区域锁定 | 换源或换出口 |
| DRM / Widevine | 加密音乐流（Spotify 音乐、Apple Music、网易云、QQ 音乐） | 不支持，永久限制；播客例外，走 RSS |
| 只返回封面图 / n challenge | YouTube 的 JS 挑战没解开 | 确认 node 或 deno 可用、`yt-dlp-ejs` 已装 |
| 文件超过体积上限 | `MAX_DOWNLOAD_MB` 太小 | 调大后重试 |
| 正文抽取为空 | 页面是反爬壳或需要登录 | 带 cookies，或改上传文本 |

失败原因不用翻日志：任务的 `stages.jsonl` 和网页上的错误条都会给出人能动手的中文说明。

## 代理的坑

这一条值得单独说，因为它是「浏览器能开、程序不能开」的头号原因。

- `HTTP_PROXY` 会被任何启动者继承——IDE、终端、沙箱、定时任务。你前几天设的那个代理端口
  很可能早已没人监听，但它还在环境变量里，于是所有请求都撞上去。
- 反过来，macOS 的「系统代理」**不会**导出成环境变量。浏览器能开、Python 用不上，
  然后被误判成「网络不稳」。
- 还有 TUN / 增强模式：直连本来就通，而 shell 里的代理变量纯属残留。

所以采集前按固定顺序探测，谁通用谁，并把结果写回进程环境：

1. 直连（显式 `trust_env=False`，绕开一切代理变量）
2. 环境变量里的代理（可能是残留的死端口）
3. macOS 系统代理（`scutil --proxy` 读 HTTPSProxy / HTTPSPort，不需要手填）

结果处理：

- 直连成功且原来有代理 → 丢掉那个死代理，`note` 里写明「已忽略失效代理」
- 直连失败、某个代理成功 → 切过去，后续 yt-dlp 与模型请求都走它
- 都不通 → 报错里逐条列出每条路径各自的失败原因

`/api/diagnostics` 返回 `mode`（direct / proxy / none）、`attempts[]`（每条路径一行）、`note`。
只有需要钉死出口时才在 `.env` 填 `PROXY_URL`（会强制覆盖继承来的代理，并自动把
`127.0.0.1` / `localhost` 加进 `NO_PROXY`）。
